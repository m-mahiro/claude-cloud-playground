DOM への重複アクセスは大きく減った

この節だけは、Tampermonkey の代わりの軽いシムで測りました。Tampermonkey のスクリプトはページとは別の実行環境で動き、ページ側で DOM API を包んでも呼び出しが見えないためです。DOM への操作の回数は、どの管理ソフトで動かしても変わりません。要素ごとに「どのスクリプト(CP Toolkit は機能)が、取得・読み取り・書き換えを何回したか」を数えると、旧スクリプトでは同じ要素を別々のスクリプトがそれぞれ探し直していました。CP Toolkit ではそれが機能の間でも少なく、書き込み直後にレイアウトを読む処理(強制レイアウトの疑い)もなくなりました。

測り方と限界

  • 旧スクリプトは、nsubaru 版8本の統合前の最終版(コミット 7c4fc38 の直前)と、SOURCES.md で「派生」「模倣」の元になった公開スクリプト18本。Chrome 拡張の2つ(Statement Lens、comfortable-atcoder)は含めていません。CP Toolkit は 1.0.26 で、ソースマップを付けるため整形前の同じ中身の版を入れました。
  • Tampermonkey 5.5.1 を入れた Chromium(headless)で、条件ごとにスクリプトを自動でインストールしました。全 — 回のうち — 回で、そのページに当てはまるスクリプトがすべて動いたことを確かめています。
  • ページは AtCoder の公開ページ9つを一度だけ録画し、計測ではそれだけを返しました。提出一覧・順位表・提出画面はログインが必要なため対象外で、提出まわりの機能(結果の平均、検索条件の保持など)は測れていません。
  • 環境はクラウドの Linux 上の headless Chromium です。絶対値より、条件の間の差を見てください。
  • DOM の計測だけは軽いシムで動かしました(上の節を参照)。children などの辿り方は数えていません。
  • 計測コードと手順: github.com/m-mahiro/claude-cloud-playground の perf-cptoolkit。
